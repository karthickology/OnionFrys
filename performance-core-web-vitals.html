Performance Optimization

Core Web Vitals

Three metrics, measured from real visitors, that quantify what "fast" actually means.

On this page

  1. LCP — Largest Contentful Paint
  2. INP — Interaction to Next Paint
  3. CLS — Cumulative Layout Shift
  4. Field data vs. lab data

LCP — Largest Contentful Paint

"LCP (Largest Contentful Paint) measures how long it takes the largest visible element—usually a hero image or headline—to render on screen. It's a Core Web Vital and a direct ranking factor. If that main element loads slowly, users perceive the whole page as slow.

The most common causes of a poor LCP score are slow server response time, render-blocking CSS or JavaScript, and unoptimized hero images. Each one is fixable—compress images, cut back on heavy scripts, and improve server speed. Tackle these, and your LCP improves fast."

INP — Interaction to Next Paint

"INP (Interaction to Next Paint) measures how responsive a page feels to real input—a click, a tap, a keypress—across the entire visit, not just the first interaction. It captures the full experience, not a one-time snapshot. If the page lags when someone actually tries to use it, INP catches that.

Heavy JavaScript execution on the main thread is the usual culprit when INP is poor. Too much JavaScript running at once blocks the browser from responding to clicks and taps. Break up long tasks, defer non-critical scripts, and your page will feel noticeably snappier."

CLS — Cumulative Layout Shift

"CLS (Cumulative Layout Shift) quantifies visual instability—content jumping around as images, ads, or web fonts load in. It's the frustration of going to click something and having it move at the last second. A high CLS score makes a page feel sloppy and untrustworthy.

The standard fixes are straightforward: reserve space for images and ads before they load, and choose font-loading strategies that avoid a visible swap. Set width and height attributes, use aspect-ratio containers, and avoid fallback fonts that cause reflows. Plan the layout upfront, and nothing shifts unexpectedly."

Field data vs. lab data

"The Chrome User Experience Report (CrUX) reflects real visitors on real devices and connections—it's actual field data from actual people. Lighthouse simulates a single run under controlled conditions in a lab. They're both useful, but they measure different things.

The two can disagree—and when they do, field data is what actually affects search ranking and real user experience. Lab results are helpful for debugging, but CrUX tells you how your site really performs in the wild. Treat it as the source of truth when the two conflict."

Field data is the scoreboard

A perfect Lighthouse score with poor field data usually means the lab test doesn't reflect what real visitors — often on slower devices and networks — actually experience.

Action checklist

  • ✓Check field data (CrUX) in Search Console, not just a lab test
  • ✓Optimize the largest above-the-fold element specifically for LCP
  • ✓Audit main-thread JavaScript for anything blocking interaction
  • ✓Reserve space for images, ads, and embeds before they load
  • ✓Re-test after any major dependency or ad-script addition
