Image Optimization

Usually the heaviest thing on the page — and the fastest win available.

On this page

  1. Choosing the right format
  2. Sizing images for how they're actually displayed
  3. Lazy loading done right
  4. Compression without visible quality loss

Choosing the right format

WebP and AVIF typically produce smaller files than JPEG or PNG at equivalent visual quality, and both now have broad browser support. PNG still has its place for images that need true transparency or sharp, flat graphics like logos.

Sizing images for how they're actually displayed

A source image larger than its largest displayed size is pure waste — responsive images with a srcset let the browser choose an appropriately sized file for the visitor's actual viewport instead of downloading a desktop-sized file on a phone.

Lazy loading done right

Native loading="lazy" defers offscreen images until they're about to enter the viewport, which is exactly what's wanted for anything below the fold. It should not be applied to the hero image or anything visible on first paint, since that would delay the very thing LCP measures.

Compression without visible quality loss

Most images can be compressed well past their original export settings before quality loss becomes visible. A rough target of under 200KB for most web images, checked visually after compression, catches the majority of savings without a perceptible difference.

The easiest win on the list

Image weight is usually the single biggest, and single easiest, performance fix available on an existing site — before touching JavaScript or infrastructure, check images first.

Action checklist

  • ✓Convert hero and large images to WebP or AVIF where supported
  • ✓Add a srcset so browsers can choose an appropriately sized file
  • ✓Lazy-load offscreen images, but never the hero image
  • ✓Compress every image before publishing, targeting well under 200KB
  • ✓Recheck total image weight whenever new pages are added
