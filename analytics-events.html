Analytics & GA4

Event Tracking

GA4 tracks everything as an event — the skill is deciding which ones are worth naming.

On this page

  1. Automatically vs. manually collected events
  2. Naming events consistently
  3. Parameters that make events useful
  4. Testing before you trust the data

Automatically vs. manually collected events

"GA4 collects a useful baseline automatically—page views, scrolls, outbound clicks, and video engagement—with no setup required. You get solid foundational data the moment you install the tag. It's enough to spot broad trends and general behavior right away.

But anything specific to your site's actual goals needs manual instrumentation. A form submission, a product configurator step, a pricing toggle—these are unique to your business and won't track themselves. Define what success actually looks like, then set up those key events before you need the data."

Naming events consistently

"Agreeing on a naming convention before implementation starts—like verb_noun (generate_lead, start_trial, view_product)—prevents one of the most common failures in event tracking. Without a clear system, teams end up with three slightly different names all tracking the same action, and suddenly your reports are a mess.

Set the rule upfront, stick to it, and everyone speaks the same language. Clean data starts with a naming convention you actually enforce."

Parameters that make events useful

"A single generic 'click' event tells you little—just that someone clicked something somewhere. Without context, it's noise. You know an action happened, but not where, why, or on what.

The same event with parameters attached—button_location, form_name, item_category—turns one event into something you can actually analyze. You can filter, compare, and segment without creating a new event for every variant. One event, endless insights."

Testing before you trust the data

"DebugView and the real-time report let you fire an event and confirm it arrived with the right parameters before it's live in production. You get instant feedback—no waiting, no guessing, no hoping it works.

A quick QA pass here catches most naming and parameter mistakes before they pollute weeks of data. Test first, fix fast, and your reports stay clean from day one."

Fewer events, better parameters

Most sites overcorrect toward tracking too many narrowly-named events instead of fewer events with rich parameters. The second approach is almost always easier to analyze later.

Action checklist

  • ✓Document a naming convention before instrumenting any custom event
  • ✓Attach parameters instead of creating a new event per variant
  • ✓Verify every custom event in DebugView before shipping
  • ✓Avoid duplicating an event GA4 already collects automatically
  • ✓Review event names quarterly for accidental duplicates
