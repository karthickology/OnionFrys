Analytics & GA4

GA4 Setup

The foundation work that determines whether every report after this one can be trusted.

On this page

  1. Property and data stream basics
  2. Connecting Search Console and Ads
  3. Defining conversions early
  4. Common setup mistakes

Property and data stream basics

One property per site keeps reporting clean; a data stream is where you configure the actual tracking code and settings for a given site or app. Data retention settings are easy to overlook and default to a shorter window than most teams expect — worth checking on day one.

Connecting Search Console and Ads

Linking Search Console surfaces organic query data directly inside GA4 reports; linking an ads account brings cost and campaign data in alongside on-site behavior, so paid performance can be judged against the same conversions as everything else.

Defining conversions early

Mark key events as conversions before a campaign launches, not after. Retroactively marking a conversion doesn't backfill historical data the way many people assume, so campaigns run before this step is done are effectively unmeasured.

Common setup mistakes

Unfiltered internal or office traffic, a missing cross-domain configuration for multi-domain checkouts, and unconfigured referral exclusions are the most common reasons a GA4 property reports numbers that look plausible but aren't accurate.

Fix it before, not after

Every day a GA4 property runs with a setup mistake is a day of data that can't be corrected retroactively. Audit the basics before trusting a single report.

Action checklist

  • ✓Confirm data retention settings match how far back you'll need to look
  • ✓Link Search Console and any ad accounts in use
  • ✓Mark key conversion events before launching a campaign
  • ✓Filter out internal and office traffic
  • ✓Verify cross-domain tracking if checkout or booking happens on a different domain

These checklists are meant to be used, not just read. Reach out if you want a second pair of eyes on your setup.
